\section{Introduction}

\begin{frame}{Motivation}
\begin{itemize}
  \item Earnings-related disclosures update expectations about future cash flows and should affect valuation.
  \item The current goal is not to force a strong pooled headline, but to build a cleaner diagnostic baseline.
  \item Tushare Pro lets us test how expectation measurement and match quality affect short-run inference.
\end{itemize}
\end{frame}

\begin{frame}{Research Question}
\begin{block}{Core Question}
Do China A-share earnings-related events generate short-run abnormal return once surprise is measured relative to stricter sell-side expectations, and how much do signal scaling and match quality change that inference?
\end{block}
\begin{itemize}
  \item Old version: guidance-only proxy design.
  \item Current version: Tushare-first diagnostic baseline with explicit event types and explicit match tiers.
  \item Final framing now emphasizes identification quality, not a forced positive finding.
\end{itemize}
\end{frame}

\begin{frame}{Why We Changed the Headline}
\begin{itemize}
  \item A pooled all-event standardized specification hides important heterogeneity.
  \item Preannouncements are cleaner than revisions, express releases, and formal releases for a default headline sample.
  \item \texttt{main\_surprise\_std} should be a robustness lens, not the only lens.
  \item Match-quality tiers should be explicit rather than silently blended.
\end{itemize}
\end{frame}

\begin{frame}{Expectation-Matching Ladder}
\begin{itemize}
  \item \texttt{strict\_same\_quarter}
  \item \texttt{same\_fiscal\_year\_nearest\_valid}
  \item \texttt{latest\_valid\_pre\_event}
  \item \texttt{multi\_report\_median}
\end{itemize}
\begin{block}{Interpretation Rule}
The headline baseline uses only \texttt{strict\_same\_quarter}; relaxed tiers are reported separately to show how benchmark construction changes inference.
\end{block}
\end{frame}

\begin{frame}{Free-data Augmentation as Diagnostic Extension}
\begin{itemize}
  \item We keep \texttt{tier\_1\_tushare\_report\_rc} as the default headline baseline.
  \item We add \texttt{tier\_2\_eastmoney\_profit\_forecast} and \texttt{tier\_3\_eastmoney\_research\_report\_text} only as labeled augmentation tiers.
  \item The goal is to study coverage-versus-quality tradeoffs, not to claim that free public proxies solve the expectation-quality problem.
  \item The main narrow comparison remains preannouncement-only, raw surprise, and CAR10-focused diagnostics.
\end{itemize}
\end{frame}

\begin{frame}{How to Read Augmentation Results}
\begin{block}{Interpretation rule}
If a free-data tier adds coverage but weakens identification materially, it should remain a supplementary diagnostic. Only if coverage expands without obvious deterioration should it be shown as an augmentation route --- not as a replacement baseline.
\end{block}
\end{frame}

\begin{frame}{What the Repository Claims Now}
\begin{block}{Recommended narrative}
This repository is best viewed as a Tushare-first diagnostic baseline with a controlled free-data augmentation layer. The augmentation layer is used to test coverage-quality tradeoffs, not to replace the core baseline or to overstate headline evidence.
\end{block}
\end{frame}

\begin{frame}{Updated Recommendation}
\begin{block}{Recommendation B+}
Keep Tushare report\_rc as the default expectation benchmark, keep preannouncement-only strict matching as the headline sample, and use Eastmoney tiers only as explicit diagnostic extensions when evaluating whether additional free coverage is worth the loss in expectation quality.
\end{block}
\end{frame}

\begin{frame}{Next Step}
\begin{itemize}
  \item Keep the Tushare event architecture and focused diagnostic outputs.
  \item Use preannouncement-only strict matching with tier\_1 as the baseline comparison set.
  \item Evaluate free-data augmentation only through separate labeled tier comparisons.
  \item Add stronger external analyst-expectation data only if the goal is a stronger final headline.
\end{itemize}
\end{frame}

\begin{frame}{Conclusion}
\begin{itemize}
  \item We kept the Tushare-first architecture and narrowed the headline sample.
  \item We now compare raw, pct, and std in parallel instead of relying on one standardized headline.
  \item We now expose strict and relaxed match tiers explicitly.
  \item We add free-data augmentation as a diagnostic extension rather than a replacement.
  \item The repository's main contribution is still a cleaner and more auditable diagnostic baseline.
\end{itemize}
\end{frame}
